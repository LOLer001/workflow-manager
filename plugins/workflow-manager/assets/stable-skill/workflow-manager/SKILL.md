# Workflow Manager

Workflow Manager is a thin continuity and authorization layer. Do not restate host-native coding, progress, tool, or multi-agent guidance.

## Route

1. Classify **Daily** or engineering **Work** independently from Direct/Focused/Complex shape.
2. Work is **Hard** only for one critical signal (production/irreversible/security/full-system delivery/host-continuity acceptance), or at least two independent strong signal groups where one is unknown-cause, cross-scope, or continuity. Device/build/deploy, three phases, a shared resource, or ambiguity alone is not Hard.
3. Ambiguous Work starts as a bounded local diagnosis. Promote only when evidence adds the required signal; do not spend an assessor turn merely because classification is uncertain.
4. Simple and Focused Work stay local. True Hard uses one highest-available assessor at `max` (`ultra` only for explicit `highest_throughout`), then a canonical plan ending `计划已就绪，等待确认后执行`. Read [work routing](references/work-routing.md).

## Solve problems instead of stopping

- Preserve the first error and make one material correction immediately.
- If the root cause is unknown, risk is critical, or that correction fails, call exactly one highest-available model at `max` for bounded diagnosis, apply the correction, and resume the original execution.
- A recoverable tool, test, host-response, path, or gate mismatch is work to solve, not a blocker. Stop only for a genuine external condition that remains after bounded alternatives.
- Never lower verification or acceptance to fit a quota. Split scope or report the typed external blocker.

## Hard authorization

- Before confirmation, permit reads and diagnostics but block Hard mutation. Store the plan in the private canonical journal; external edits invalidate it.
- Use 1..6 manifest slices, normally 1..3. A slice is an acceptance checkpoint, not a reason to repeat the full plan or create an unnecessary lane.
- Confirmed execution keeps one mutation owner. PreTool records `requested`, PostTool records `host_accepted`, and bound Start must be fully observed from official model plus same-turn host effort; never infer runtime identity from request fields or child prose.
- Parent verification must use structured host evidence. One materially corrected recovery is allowed; never revive a terminal executor or weaken acceptance. Read [confirmed execution](references/confirmed-execution.md).

## Minimal gates and context

- Hard-deny only authorization/destructive scope, unconfirmed Hard mutation, conflicting ownership/resource use, mounted-tree Git, or stale/forged contract evidence.
- Builds, logs, recordings, native Git status, large output, and repeated read-only probes are telemetry, not denial reasons. Large results remain available without repeated additionalContext.
- Emit route context only for a new/changed decision. At 70% context, checkpoint once and resume from the native summary plus canonical plan; do not emit a 55% warning or stage-action budget.
- Reuse success only when inputs, files, external state, freshness, and evidence are unchanged. Never reuse failure.

## Delegation and continuity

- Delegate only ready, independent, positive-utility ownership. Caps are live/reserved ceilings, not lifetime quotas: Complex 2, Extensive 3. Capacity is reusable after a terminal lane.
- A child may create a read-only non-overlapping lane through the same route/cap checks; child-origin mutation remains denied.
- Cross-task coordination requires a fresh same-host conflict on the same resource. Read [live coordination](references/live-coordination.md) and [agent lifecycle](references/agent-lifecycle.md).
- Compaction resumes from native summary, bounded state, and canonical plan. Same-task regressions use [regression continuity](references/regression-continuity.md); explicit fidelity work uses [reference acceptance](references/reference-acceptance.md).

## Fixed boundaries

Never run Git from CIFS, Samba, UNC, DrvFS, or another mounted working tree. Use an authoritative native Linux clone or remote Git. Profiles are requests until host acceptance and Start echo prove them. User instructions, safety, project-local skills, and required acceptance take precedence.
